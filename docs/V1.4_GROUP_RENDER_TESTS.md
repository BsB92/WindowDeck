# WindowDeck 1.4.0 — grouped list rendering regression test

This test targets a reported UI ordering regression: after automatic refresh, a window/group row appeared **above** its expected application group. Clicking a row caused another refresh and repaired the layout.

The proposed fix batches all rows and headers into a complete ordered list before updating the WinForms flow panel. This is a suspected cause, **not a confirmed reproduction or a guaranteed fix**. Requires local Windows 11 testing.

## Test on `fix/v1.4-group-layout-order`

- [ ] Build and launch WindowDeck with application grouping ON and auxiliary windows ON.
- [ ] Open many windows from multiple applications (e.g. Excel, Explorer, PowerPoint, Notepad++), leaving WindowDeck visible.
- [ ] Open, close, minimize, restore and retitle windows rapidly; watch the list during and just after each automatic refresh.
- [ ] Check that **every application header remains directly above its own rows**, and that no row moves above or between another application's header/rows.
- [ ] While windows are being opened/closed, switch window focus by clicking a WindowDeck row; confirm that header/row ordering remains stable **before** and **after** the click.
- [ ] Toggle collapsing of application groups, expand a Notepad++ Find auxiliary subgroup, and repeat the window operations.
- [ ] Turn grouping OFF, repeat with and without Search, then turn grouping ON and verify alphabetical application groups.
- [ ] Enable Presentation Mode, move one row into/out of Presentation group, and ensure that the presentation header stays first and ordinary groups remain ordered below it.
- [ ] With 3 or 4 displays, move windows between displays while WindowDeck is open; verify no transient row/header reordering.
- [ ] Check that opening the panel after hiding it does not reorder groups or reset collapse states.
- [ ] If the issue reappears, capture **a screenshot before clicking anything**, the affected app/group names and the operations performed immediately before it. Compare after a click-triggered refresh.
