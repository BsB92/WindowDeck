# WindowDeck 1.4.0 — working regression checks

This is a working checklist for changes proposed for 1.4.0, not proof of successful Windows testing.

## Event-driven refresh and application grouping

1. Open several Excel, PowerPoint, Notepad++ and Explorer windows. Check that entries belong to the correct application group.
2. Continuously drag an external window for more than 10 seconds while WindowDeck is visible. Confirm that changes to its displayed screen are reflected during the drag, rather than only after movement stops.
3. Open, close and rename several windows rapidly. Check that new windows appear, closed windows disappear and names/group headers stabilize shortly after the final event.
4. With **Show auxiliary windows** enabled, open Notepad++ Find. Check that Find appears as a subgroup of the correct parent window, including after rapid changes and switching search on/off.
5. Toggle Group windows by application and switch the UI language. Confirm there are no duplicate or stale groups.

## Visible flyout Z-order

1. Open WindowDeck with the hotkey. Activate a normal Excel/Explorer window through its row and verify that WindowDeck remains visible above it, without taking focus back.
2. Repeatedly hide/show WindowDeck, change the active monitor, and activate several normal windows. Check that the flyout remains topmost on each opening.
3. Open Settings and Help and verify those dialogs remain usable and above the flyout when relevant.
4. Check behavior against other applications explicitly marked topmost, full-screen content and elevated windows. Log exact application, display and reproduction steps for any conflict; Windows does not guarantee that one topmost application always outranks every other topmost window.

## Presentation Mode — current protection regression (new bypass not implemented yet)

1. Enable Presentation Mode, choose screen 2 as the reserved screen and add one allowed window to the Presentation group.
2. Lock protection. Move an unapproved window toward screen 2; confirm that the **existing** protection eventually redirects it to another screen. Note any flashes or failure to redirect.
3. Confirm that an allowed Presentation group window can still be used on screen 2.
4. Disable protection and confirm that normal window movement onto screen 2 works.
5. The requested completely invisible transit from screen 1 to screen 3 via protected screen 2 is **not yet implemented**; do not mark it as passing. Track separately in issue #43.

## Taskbar personalization — duplicate WindowDeck history (separate branch)

**Use branch `fix/v1.4-tray-history` / PR #45 for these tests, not the current refresh/topmost branch.**

1. In Windows 11 **Settings > Personalization > Taskbar > Other system tray icons**, record whether multiple WindowDeck entries appear. Distinguish them from multiple simultaneously visible live tray icons.
2. Exit WindowDeck through **Tray > Exit**, then close Taskbar Settings. Preview only from the repository root:
   `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Clear-WindowDeckTrayHistory.ps1`
3. Confirm that each previewed executable path belongs to WindowDeck, and that no unrelated applications appear. Do not apply if the preview looks wrong.
4. Only after inspecting the preview, run with `-Apply`, confirm that backups were created under `artifacts\tray-icon-backups`, and confirm that no other app keys were targeted.
5. Sign out/in (or restart Explorer) and reopen Taskbar Settings. Confirm whether stale entries disappeared. Start a released EXE from one permanent path and confirm the current icon appears correctly.
6. After running a Visual Studio build, check whether another Windows history entry appears; log this OS-managed behavior separately from actual duplicate live icons.
