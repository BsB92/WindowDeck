Branch: feature/v1.4-integrated-window-sets. It contains the work from PR #42, #45, #47 and the Saved sets feature. PRs are still unmerged.
**Required**: Build and test on Windows 11; GitHub connector access cannot compile or run the application.

- [ ] Uncheck one workbook, then save a named set. Verify only checked entries appear in its details.

- [ ] Save several differently named sets and confirm alphabetical listing and persistence after restarting WindowDeck and Windows.
- [ ] Duplicate set names are rejected case-insensitively.
- [ ] Rename a set, update a set from current window selection (with confirmation), delete one (with confirmation), then reopen the manager.

## Additive restore
- [ ] Save a set with two **local** Excel workbooks and two Explorer folders, then close those resources normally (save your work first!).
- [ ] Open the saved set. Confirm supported resources are requested to reopen from their real paths.
- [ ] Leave one saved workbook open before opening a set; verify it is not duplicated if Office reports the exact file path.
- [ ] Open the same set again: no duplicate requests from WindowDeck in the current session.
- [ ] Include missing/moved documents; they must be reported, and other resources should continue opening.
- [ ] Include unsupported browser tabs, unsaved workbook, virtual Explorer folder; they should be reported as not automatically restorable.
- [ ] During all tests, existing windows not in a set must **never be closed**.
- [ ] After an OS reboot, existing sets must still be listed.
- [ ] Try multiple Excel instances and Microsoft 365/SharePoint files; note that COM may not expose a reliable path, so some resources may be marked unsupported.

### Technical limits
Office documents are resolved by COM automation by exact native window handle; Office may not expose every window/instance through this interface. No generic title-to-file guessing occurs. File Explorer tabs/virtual folders and browser pages are not reliably restorable. Success in starting a file association means only that a Windows open request was sent, not that the app finished loading it.
