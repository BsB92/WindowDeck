# WindowDeck 1.4.0 — integrated local Windows 11 acceptance

Branch: feature/v1.4-integrated-window-sets. It contains the work from PR #42, #45, #47 and the Saved sets feature. PRs are still unmerged.
**Required**: Build and test on Windows 11; GitHub connector access cannot compile or run the application.

## Preparation
- [ ] Fetch and switch the integrated branch in Visual Studio.
- [ ] Run dotnet build -c Release and inspect introduced errors/warnings.
- [ ] Verify About reports 1.4.0; run the final published executable separately after building.
- [ ] Confirm the existing tray icon, hotkey and settings still work.
- [ ] Use a copy of non-confidential documents for testing.

## Save / choose windows
- [ ] Click **Zestawy okien / Saved sets** beside Presentation Mode.
- [ ] Select **Zapisz obecne / Save current** with Excel, Word, PowerPoint and File Explorer windows present.
- [ ] All listed checkboxes must be **selected by default**.
- [ ] **Odznacz wszystkie / Deselect all** clears every checkbox; **Zaznacz wszystkie / Select all** selects every one.
- [ ] Uncheck one workbook, then save a named set. Verify only checked entries appear in its details.
- [ ] Saving with zero checked entries is blocked; saving with blank name is blocked.
- [ ] Check unsupported items (browser windows, unsaved documents, dialogs): marked as unsupported, yet independently selectable.
- [ ] Save several differently named sets and confirm alphabetical listing and persistence after restarting WindowDeck and Windows.
- [ ] Duplicate set names are rejected case-insensitively.
- [ ] Rename a set, update a set from current window selection (with confirmation), delete one (with confirmation), then reopen the manager.

## Additive restore
- [ ] Save a set with two **local** Excel workbooks and two Explorer folders, then close those resources normally (save your work first!).
- [ ] Open the saved set. Confirm supported resources are requested to reopen from their real paths.
- [ ] Leave one saved workbook open before opening a set; verify it is not duplicated if Office reports the exact file path.
- [ ] Open the same set again: no duplicate requests from WindowDeck in the current session.
- [ ] Include missing/moved documents; they must be reported, and other resources should continue opening.
- [ ] Include unsupported browser tabs, unsaved workbook, virtual Explorer folder; they should be reported as not automatically restorable.
- [ ] During all tests, existing windows not in a set must **never be closed**.
- [ ] After an OS reboot, existing sets must still be listed.
- [ ] Try multiple Excel instances and Microsoft 365/SharePoint files; note that COM may not expose a reliable path, so some resources may be marked unsupported.
- [ ] Check that the local JSON file contains no process IDs, runtime HWNDs or application credentials.

## Regression checks
- [ ] Continuously open/close windows for 10+ seconds while WindowDeck is visible; updates keep flowing.
- [ ] Grouped row headers remain in order after refresh, click, search, group collapse and auxiliary-dialog toggles. Capture a screenshot **before a click** if a group jumps.
- [ ] Always on top: activate Excel/Explorer via WindowDeck and verify the flyout remains above ordinary non-topmost windows.
- [ ] Presentation Mode and its existing reactive screen protection remain functional. Invisible cross-monitor transit is NOT implemented in this branch.
- [ ] Settings > Konserwacja / Maintenance: inspect old-tray-record list and do not delete entries without first reviewing paths and backup behavior.
- [ ] Repeat in Polish and English, light and dark themes.

## Release
- [ ] Publish with scripts/Prepare-Release.ps1 (requires the v1.4.0 release notes template).
- [ ] Test the resulting artifacts/WindowDeck-1.4.0-win-x64/WindowDeck.exe outside Visual Studio.
- [ ] Do not merge or publish before acceptance and checksum verification.

### Technical limits
Office documents are resolved by COM automation by exact native window handle; Office may not expose every window/instance through this interface. No generic title-to-file guessing occurs. File Explorer tabs/virtual folders and browser pages are not reliably restorable. Success in starting a file association means only that a Windows open request was sent, not that the app finished loading it.
