# WindowDeck 1.4.0 — release-candidate checklist

This is a release candidate, not a published release. Work from PRs #42, #45, #47 and #49 is included in integrated PR #50, but it is **not yet merged to master**.

## 1. Test the integrated branch

In Visual Studio Git UI, fetch and switch to `feature/v1.4-integrated-window-sets`. Close any existing WindowDeck process using its tray menu, then build and launch.

Run the complete test plan in [V1.4_FULL_VALIDATION.md](V1.4_FULL_VALIDATION.md), including:
- Saved sets, all-selected-by-default checkbox behavior, multiple named sets, supported document reopen and prevention of duplicate opens.
- Event refresh, group list ordering, Always on top and Settings icon-history cleanup.
- Polish/English, multiple monitors and Presentation Mode regression tests.

Windows-only application integration **requires local user acceptance** even after a successful CI build.

## 2. Prepare a single-file executable

Run in PowerShell from the repository root:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Prepare-Release.ps1
```

The script reads Version=1.4.0 and creates `artifacts\WindowDeck-1.4.0-win-x64\`, including:
- `WindowDeck.exe` (self-contained)
- `WindowDeck.exe.sha256`
- `RELEASE_NOTES.md` with the actual executable hash substituted into the template

Run the executable from this folder **outside Visual Studio** and perform acceptance tests again. The release cannot be validated only by compiling.

## 3. Accept and prepare the actual release

Only after user approval: resolve or close obsolete draft PRs without duplicating commits, merge the integrated changes to master, and prepare tag `v1.4.0` on the accepted commit. If master changes functional code, publish a fresh build and retest before tagging.

Use the actual tested executable and checksum in GitHub Releases. Keep `README.md` pointing to the currently published version until the release is public.

## 4. Installation and saved data

For normal use, keep the published EXE in a single permanent folder to avoid new historical Windows notification icon records. Updating the EXE does **not** erase locally saved window sets (`%LocalAppData%\WindowDeck\window-sets.json`) or normal settings.

Do not publish any 1.4 release until all relevant tests are confirmed.
