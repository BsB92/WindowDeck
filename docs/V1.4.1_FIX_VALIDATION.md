# WindowDeck 1.4.1 — local Windows acceptance tests

This hotfix addresses two reported regressions. A build and the data-order tests are not substitutes for running the actual Windows flyout.

## Mixed-DPI monitor placement

- [ ] Run WindowDeck on Windows 11 with a 3840 × 2400 display at 250% scaling and at least one other display with a different scale (100%, 125%, 150% or 200%).
- [ ] Place the cursor on the 250% screen, press the global shortcut and verify the flyout is visible inside that screen's working area, aligned to its right edge and above the taskbar.
- [ ] Repeat with the tray Open action while an external window on that screen is foreground.
- [ ] Hide and reopen the flyout on a differently scaled monitor, then return to the 250% display. Check text, search, row buttons, width and scrolling.
- [ ] Try dynamic Windows scaling changes (where practical) and connect/disconnect an external display. Check that the flyout can be opened afterward.
- [ ] Confirm monitor numbering, moving selected windows and Presentation Mode still use the correct monitors.

## Application grouping and manual refresh

- [ ] Open multiple Excel workbooks plus ChatGPT, File Explorer, PowerPoint and Notepad++ windows; include several Excel processes if possible.
- [ ] Repeatedly hide/reopen WindowDeck without interacting with any group. Every group should appear once, with only its own windows, and each group and its rows sorted A–Z.
- [ ] Rapidly create, close, restore, minimize, retitle and move windows across monitors while the flyout is visible. Confirm stable grouping before clicking group headers.
- [ ] Use the new refresh button beside Search. It must re-enumerate windows, reload application metadata, repair list order, and preserve the current search and collapsed-group state.
- [ ] Test auxiliary-window subgroups, collapsed groups, Presentation Mode and grouping disabled, plus English, Polish, light and dark themes.
- [ ] Confirm normal event-driven updates still work without clicking Refresh, and that idle CPU remains near zero.

## Release gate

- [ ] `dotnet build WindowDeck.csproj -c Release`
- [ ] `dotnet run --project tests/WindowRelationships/WindowRelationships.csproj -c Release`
- [ ] Run the Windows-specific tests above on the 250% display before calling the reported monitor issue fixed.
- [ ] Do not merge to master or publish the release until the local checks pass.
